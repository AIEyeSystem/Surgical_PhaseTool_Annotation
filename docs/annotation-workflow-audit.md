- **撤销/重做**：当前图像最多 100 步；每个完成的图形或删除为一步，拖动在松开鼠标时记为
  一步；切换图像后重新开始。
- **Video/Frame 切换复审**（9 项已复现、3 项代码审读）：打开其他项目放弃未完成区间后仍
  残留旧区间；视频 Case 的上一张/下一张可进入未关联的关键帧截图，导致保存永远失败；在
  Video 中加载 SAM 后返回 Frame 不编码；在 Video 中改设置会刷新隐藏画布并开放编辑；关键帧
  截取被无关取消吞掉；忙碌时返回视频不定位；取消打开视频仍切换模式；切换语言丢失标题和
  未保存标记；SAM 加载失败后提示面板复现；追踪提交后保存可能覆盖磁盘上的新标签。均已修复，
  新增 `test/test_video_frame_switching.py`（15 项）。

- **文件列表与批量操作**：文件列表新增文件名筛选（支持 `*`/`?`）、按类别“包含/不包含”
  筛选及各类别图像数；筛选只隐藏行，不改变 `files_list` 和上一张/下一张。“批量…”对话框可
  删除某类别标注、重命名/合并类别（全部 / 筛选结果 / 当前图像，执行前预览数量）。每次批量
  操作都先备份到 `<标签目录>/.ivas_batch/<时间>-<操作>/` 并写入 `history.jsonl`；“撤销最近一次”
  按内容哈希校验，文件之后被改动则拒绝撤销并列出文件。
- **SegMiss / SegAll 卡住**：不是死锁。批处理在图像编码器持有同一把可重入模型锁时无限等待，
  且等待期间无法取消、界面一直显示 0/N；收尾时若刷新出错，对话框永远无法关闭；SegMiss 还会先
  完整解码每张图再判断标签。现在等待可在 50 ms 内取消并显示“正在等待 SAM 模型”，收尾一定完成，
  SegMiss 只读 JSON 判断是否缺类别，汇总列出无检测结果的图像。单图“分割”无结果时提示
  “未在当前图像中找到「类别」”。
- **“Wait for SAM image encoding to finish”**：SAM3.1 的分割依赖当前图像的编码缓存，切换图像
  后立即点“分割”会被拒绝；中止 SegMiss 后正在处理的那张图仍会推理完，编码因此更晚，问题更常见。
  现在“分割”和视觉提示“预测”在编码未完成时会排队，编码完成后自动执行；切换图像、显示模式或
  模型、编码失败都会取消排队。重复点击不会重新开始正在进行的编码，状态栏显示“SAM 正在编码当前
  图像…”。另外修正了三个测试夹具未屏蔽配置保存、关闭窗口时写入用户 `software.yaml` 的问题。
- **视觉提示点**：SAM3 概念分割只接受文本和框示例，不接受点（`sam3_image.py` 会忽略点）。
  因此 “+ 点 / − 点” 先用单目标点提示得到点击处的目标，再以其外接框作为正/反例框参与概念
  分割；含反例点的结果被去除，正例点的目标保证保留。

## 结论与三个目标

原实现已经复用了同一分割画布，也有独立的视频项目存储，但不能据此认定解耦完善。
主要问题在编辑上下文和撤销边界：仅用“存在视频项目”判断是否启用视频功能，以及
用整个项目快照实现“时序撤销”，会让独立分割和混合工作流相互影响。本次已修正这些边界。

| 目标 | 当前使用方式 | 数据及模型边界 |
| --- | --- | --- |
| 单独标注视频 Phase | File 打开视频，自动进入 Video；选择 Phase、标签，记录开始/结束 | 只需媒体解码和视频项目；无需加载 SAM，也无需创建任何分割帧 |
| 单独进行分割，可使用 SAM3.1 | File 打开图像目录，自动进入 Frame；手工绘制或使用 SAM 提示 | 使用原有 Annotation/Polygon 画布和图像模型接口；无需视频项目 |
| 视频标注期间分割某帧 | Mode → Frame，或“标注当前视频帧”；完成分割后保存，再 Mode → Video | 按播放位置抽帧，复用同一画布；视频项目记录帧号、时间戳、图像及标签路径；未结束区间保持在原视频工作区 |

Mode 表示正在显示的编辑器，项目表示数据归属，二者分别判断。Frame 可以是独立图像，
也可以是当前视频中的某一帧。不能用 Mode=Frame 推断“没有视频上下文”，也不能用
“已打开过视频”推断所有后续图像都属于那个视频。

| 入口 | 明确职责 | 本次处理 |
| --- | --- | --- |
| Mode | 手动切换 Video / Frame，并显示实际模式 | 放在 Project 前；打开视频/图像、完成抽帧都会自动同步；失败或取消保留原模式 |

| Frame annotation / Frame tools | 多边形、点框提示、编辑及图像显示 | 复用已有分割能力；Video 预览中禁用帧操作 |
| Video annotation / Video tools | Phase/Task、关键帧、评分、模板、校验 | 统一用户可见名称；撤销只处理视频标注和模板 |
| Tracking | 传播种子、暂存、审阅提交、回滚 | 继续使用事务流程；不与手工保存混为一体 |
| SAM | 模型选择和管理 | 模型能力由所选模型决定，与是否打开视频分别判断 |
| Tools | 格式转换、批处理等独立辅助功能 | 保留工具用途，避免自动把批量抽帧当作当前视频帧的项目关联 |

Project 原先确实大幅重复 File。另两组重复入口也已收起：视频组件嵌入主窗口后，隐藏
它内部的 Open/More，以及右侧重复的 Phase/Task 标签、开始/结束控件。主工具栏负责录入，
右侧保留未完成区间状态、覆盖率、评分和记录列表。单独使用视频组件时仍有完整操作界面。

菜单和工具栏使用同一 QAction 的快捷入口可以保留，这类重复不会产生第二套保存或状态逻辑。
“关键帧截图”和“帧分割”应继续分别存在：前者生成时间点记录并链接图像，后者创建分割标签。
“批量视频转帧”和“标注当前视频帧”也用途不同：后者才负责当前 Case 的精确帧关联。

## 修正的正确性问题

1. **打开目录和拖拽绕过未保存检查。** 两种入口现在统一到图像加载方法，先验证目标，
   再处理保存/放弃/取消；损坏或缺失的目标图像不替换现有画布。未完成图形必须先完成或取消。
2. **独立图像可误操作旧视频。** 视频动作判断当前视图及帧所属项目路径，独立 Frame 下
   禁用保留的视频控件；手动切回 Video 可继续原区间。
3. **异步抽帧抢回界面。** 打开独立图像时取消抽帧，并在接收结果时检查取消状态，
   包括已经进入 Qt 事件队列的完成信号。
4. **时序撤销回退整个项目。** 历史快照现在只包括 `temporal_annotations` 和
   `temporal_templates`；帧链接、媒体信息、对象身份、追踪状态都不受影响。
   保存帧、更新媒体和追踪也不清掉视频标注的 redo。
5. **重复打开帧使 saved 降级为 pending。** 已保存且仍存在的对应标签文件保留 saved。
6. **标签写入成功但项目关联保存失败仍显示已保存。** 此时保持未保存状态，明确报告错误，
   重试保存可补齐索引；不把 JSON 和清单跨文件写入伪装成一个原子事务。
7. **自动保存失败可能残留干净状态。** 保存前先标记修改；失败后保留编辑和未保存状态。
8. **视频快捷键影响帧画布。** 在视频帧上编辑时，画布保留帧快捷键；只有视频面板或播放
   控件拥有焦点时才启用视频快捷键。输入框编辑时继续禁止视频单键快捷操作。
9. **SAM 迟到结果或重名图像串用。** Video 中的编码完成信号不能启用分割动作；文本预测
   校验模型代次、图像序号、完整路径和当前模式，避免不同目录的同名图像接收旧结果。
10. **窄窗口工具栏裁字和隐藏窗口恢复面板错误。** 按文字宽度设置工具按钮下限；
    用面板自身的隐藏状态记录恢复目标，而非把父窗口不可见误判成面板被用户关闭；
    检查面板使用滚动容器，避免小窗口下的分类按钮伸出面板。

## 存储和兼容性

- 新品牌、窗口、启动横幅、转换器、文档、翻译资源和构建配置使用 IVAS。
- 新文件使用 `description: IVAS`、`ivas.yaml`、`project.ivas.json`。
- 接受旧 IVAT / IVAS 标签、配置和项目文件；打开旧项目后仍保存到其原路径，不复制生成
  一个平行项目。插件兼容 `ivat.plugins` / `ivas.plugins`，旧启动命令保留为别名。
- 内部 `IVAS` Python 包名、`TemporalAnnotation` 类型和 `temporal_annotations` 字段保留，
  避免破坏插件、模型配置和已有数据。历史记录与旧构建产物也不改写为新版本。
