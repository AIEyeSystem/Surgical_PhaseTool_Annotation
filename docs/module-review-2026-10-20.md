## 主要问题

### R01 · P1 · 追踪线程保存旧项目副本，会覆盖已经保存的时序标注

**位置：** [TrackingWorker](../IVAS/widgets/video_annotation_workspace.py#L178)、[界面提交项目修改](../IVAS/widgets/video_annotation_workspace.py#L1391)、[追踪暂存](../IVAS/video/tracking.py#L273)、[整个项目写盘](../IVAS/video/project.py#L2017)。

追踪线程重新加载一份 `UnifiedVideoProjectStore`；界面仍持有另一份，并可以继续保存 Phase/Task。追踪开始后只禁用启动追踪动作，没有冻结时序修改。两份 store 都以整个 JSON 覆盖项目文件。原子替换能避免半个 JSON，不能防止旧快照覆盖新内容。

**已复现：** 用确定的执行交错，在追踪传播期间让界面 store 添加并保存一个区间，磁盘区间数为 1；随后追踪 store 完成暂存，磁盘区间数变成 0。完成回调再次加载磁盘项目，界面也接受了丢失后的版本。类似竞争还涉及帧链接、时间索引和其他项目属性。

**修复及验收：** 项目文件采用单一写入者；工作线程返回追踪增量，由主项目服务应用。增加项目修订号和冲突检测；单纯给写文件操作加锁不足以修复旧副本覆盖。验收应强制交错“追踪进行中 → 保存区间 → 完成/取消/失败”，保证两类修改都保留。

### R02 · P1 · 人工修改追踪结果后，下一次提交仍可覆盖修正

**位置：** [顶点修改](../IVAS/widgets/polygon.py#L303)、[对象序列化](../IVAS/widgets/polygon.py#L531)、[提交时的人工保护规则](../IVAS/video/tracking.py#L436)。

画布修改只更新几何与未保存状态，原来的 `source="tracking"`、`review_status="draft"` 保持不变。追踪提交仅用 `source != "tracking"` 判定需要保护的人工对象，所以修正后的对象仍被当作可替换追踪结果。

**已复现：** 第一次提交后，在真实画布中将一个顶点改为 `[12, 12]` 并保存；第二次提交使用 `replace_manual=False`，该点仍被替换回 `[2, 2]`。此外，种子选取没有完整执行“已复核才能传播”的约束：有身份字段的对象不一定被更新为 reviewed。

**修复及验收：** 建立明确的“人工修订”状态，所有几何、类别等人工编辑统一触发；保留原始算法来源作为独立元数据。提交保护应识别人工修订。是否视为“已复核”应由明确的审阅动作决定。验收覆盖修改顶点、整体移动、类别编辑、重新传播和显式允许覆盖两种情况。

### R03 · P1 · 追踪回滚没有完整的文件事务，成功后也遗留错误帧状态

**位置：** [rollback](../IVAS/video/tracking.py#L508)。

回滚先复制或删除各帧标签，最后才在 store 事务中更新运行状态并保存。该事务只保护内存快照，无法撤销前面已经进行的文件操作。多个文件恢复到一半出错时，同样没有补偿。正常回滚也没有恢复提交前的 `spatial_frames` 状态。

**已复现：** 注入项目保存失败后，新建标签已被删除，磁盘项目仍记录追踪 `committed`、帧 `saved`。在不注入错误的正常回滚中，运行变为 `rolled_back`，标签不存在，但帧仍为 `saved`。

**修复及验收：** 先验证全部备份，记录标签和帧元数据的前后状态；失败时执行补偿，进程意外退出则依靠持久化事务记录恢复。验收包含第 N 个文件失败、备份丢失、项目保存失败和正常回滚，核对文件内容与项目状态一致。

### R04 · P1 · 标签加载失败后仍允许保存，可把损坏文件覆盖成空标注

**位置：** [图像及标签切换](../IVAS/widgets/mainwindow.py#L3952)、[标签加载](../IVAS/widgets/mainwindow.py#L4043)、[异常处理](../IVAS/widgets/mainwindow.py#L4086)、[save](../IVAS/widgets/mainwindow.py#L3878)。

图像预检成功后，旧画布被清空、保存动作被启用，随后才解析标签。标签异常只打印到控制台，没有明确阻止保存。`save()` 也不校验标签是否成功加载。非预期标注格式返回空对象的路径存在相同风险。

**已复现：** 标签内容为不完整 JSON `{"info":` 时，`load_finished=False`、保存动作仍启用、警告次数为 0；执行保存后，原文件被替换为 `objects=[]` 的合法 JSON。

**修复及验收：** 先将图像和标签完整解析为临时模型，成功后再替换当前编辑状态；加载失败时保留原文件、提示具体原因并禁用覆盖保存。分别验收损坏 JSON、错误格式标识、错误对象结构和损坏几何。

### R05 · P1 · 删除顶点不设置未保存状态，切换图片可直接丢失修改

**位置：** [删除选中图形或顶点](../IVAS/widgets/canvas.py#L772)、[removePoint](../IVAS/widgets/polygon.py#L226)。

删除后仍有三个或更多顶点时，只调用 `removePoint()`；该方法重绘但不触发修改通知。删除整个多边形的路径有未保存处理，删除单个顶点的分支遗漏了。

**已复现：** 一个已保存四边形删除一个顶点后，画布为 3 个顶点，磁盘仍为 4 个，`saved` 仍为 True。因此离开图片时不会走应有的未保存检查。

**修复及验收：** 为增加、移动、删除顶点建立同一个修改入口，统一更新未保存状态、面积、审阅状态及事件通知。验收删除后切图、自动保存、关闭窗口；OBB 还应禁止产生无效角点拓扑。

### R06 · P1 · SAM2 / SAM2.1 / SAM3 视频追踪调用异步加载器时缺少必填参数

**位置：** [追踪适配器](../IVAS/video/tracking.py#L184)、[加载器调用](../IVAS/segment_any/segment_any.py#L519)、[加载器定义](../IVAS/segment_any/sam2/utils/misc.py#L109)。

追踪适配器固定启用 `async_loading_frames=True`，但 facade 只传入 5 个参数，当前 `AsyncVideoFrameLoader` 还要求 `compute_device`。

**已复现：** 分别设置 `model_source` 为 sam2、sam2.1、sam3，调用真实 facade 的 `init_state()`，均得到 `TypeError: ... missing 1 required positional argument: 'compute_device'`。这一步不需要模型权重即可确认接口不匹配；SAM3.1 走另外的分支，不应据此断言它有同一个错误。

**修复及验收：** 显式传入计算设备，并为所有后端增加加载器契约测试；随后用少量真实视频帧完成初始化、种子输入、传播和取消的集成验收。

### R07 · P1 · 转换器共享类级字典，连续转换会混入上一批数据

**位置：** [共享 annos](../IVAS/formats/ivas.py#L88)、[YOLO 导入](../IVAS/widgets/converter_dialog.py#L212)、[LabelMe 导入](../IVAS/widgets/converter_dialog.py#L334)。

`annos={}` 定义在类上，各格式实例共享；部分公共读取函数清空它，界面的部分转换入口则直接追加。结果既可能被其他实例清空，也可能继承上一轮数据。

**已复现：** COCO、YOLO 实例的 `annos` 是同一字典；清空一个会清空另一个。连续新建两个 YOLOConverter 分别转换独立目录，第二个输出目录包含本不应出现的 `first.json`，以及本批的 `second.json`。

**修复及验收：** 在实例初始化时创建字典，每次任务建立独立上下文；不要依赖界面调用顺序清理全局状态。验收不同格式、不同批次、失败后重试，以及未来改为后台线程后的并发隔离。

### R08 · P2 · VOC 语义导出把第一个前景类别编码为背景

**位置：** [类别编号](../IVAS/formats/voc.py#L44)、[背景初始化](../IVAS/formats/voc.py#L75)、[界面对应编号](../IVAS/widgets/converter_dialog.py#L458)。

背景像素默认是 0，类别又从 0 开始编号；类别列表没有显式 `__background__` 时，第一个前景与背景重合。导入器生成的仅前景类别配置可以直接走到这个导出入口，不必先经过主画布补背景。

**已复现：** 唯一类别 `tool`、有明确多边形的输入，导出的整张 PNG 唯一像素值为 0。

**修复及验收：** 固定保留背景编号 0，建立一致的类别映射，对未知类别报错。验收只有前景类别、背景位置变化、未知类别，以及类别数超过输出位深容量的情况。

### R09 · P2 · LabelMe 无 group_id 的独立目标被合并，备注也无法往返

**位置：** [group_id 读取](../IVAS/formats/labelme.py#L154)、[备注写入](../IVAS/formats/labelme.py#L111)、[备注读取](../IVAS/formats/labelme.py#L162)。

所有 `group_id=None` 的形状都转为 group 0，而下游按类别和 group 合并实例。备注写到 `description`，读回却取 `note`。

**已复现：** 两个同类独立多边形导入后 group 都为 0，再导出 YOLO 只剩一条实例记录；备注 `keep this note` 经 LabelMe 往返后变为空串。

**修复及验收：** 未分组形状各分配独立 group，保留明确共享的 group；对齐备注字段并兼容旧数据。验收独立目标、共享实例、多轮往返及空备注。

### R10 · P2 · 过滤掉全部 crowd 目标后，YOLO / VOC detection 导出崩溃

**位置：** [YOLO 空列表访问](../IVAS/formats/yolo.py#L308)、[VOC 检测框计算](../IVAS/formats/voc_detection.py#L99)。

按组和类别进入导出后，如果 `keep_crowd=False` 把全部对象过滤掉，YOLO 仍访问 `segmentations[0]`，VOC detection 仍对空坐标求最小值。

**已复现：** 分别得到 `IndexError: list index out of range` 和 `ValueError: min() arg is an empty sequence`。部分外层 API 使用 `raise "..."`，还会把原异常变成不相关的 TypeError。

**修复及验收：** 空对象集合正常跳过；批次结果区分成功、跳过和失败。采用实际异常类型并保留异常链。验收全 crowd、混合 crowd、空文件和过滤背景组合。

### R11 · P2 · COCO 导出跨类别收集 crowd 值，生成空 annotation

**位置：** [category / crowd 分组](../IVAS/formats/coco.py#L224)。

外层已筛选当前类别，crowd 值却从整个 group 取。某个 crowd 值仅存在于另一类别时，内层生成空集合，后面仍输出 annotation。

**已复现：** 同一 group 下两个不同类别、不同 crowd 值的对象，导出成 4 条 annotation，其中 2 条 segmentation 为空。

**修复及验收：** 按实际存在的 `(group, category, iscrowd)` 组合生成结果，跳过空组合，并校验 area、bbox 和 segmentation 一致。验收输出对象数和几何均正确，不能只检查 JSON 可读。

### R12 · P2 · 格式层的 IVAS 数据模型落后于编辑器模型，内部往返丢字段

**位置：** [格式层对象定义](../IVAS/formats/ivas.py#L62)、[读取](../IVAS/formats/ivas.py#L204)、[写入](../IVAS/formats/ivas.py#L252)。

编辑器的 `Annotation/Object` 已支持 OBB、对象/轨迹身份、来源和复核状态；转换器仍有另一套较旧的 `ANNO.OBJ`，没有保存这些字段。

**已复现：** 一个由编辑器模型生成的 IVAS 对象，经过 `load_one_ivas_json → save_one_ivas_json` 后，`is_obb`、`object_id`、`track_id`、`source`、`review_status` 全部消失。这是同格式往返的丢失，不只是外部格式表达能力受限。

**修复及验收：** 使用共享的规范数据模型和序列化器；外部格式无法表达的字段明确报告或使用附属元数据。验收同格式语义无损、旧版本兼容，以及转换后继续做 OBB 编辑和追踪关联。

### R13 · P2 · 多边形差集忽略内部孔洞，结果区域错误

**位置：** [布尔运算结果重建](../IVAS/widgets/canvas.py#L899)，尤其 `geom.exterior.coords` 所在的 948 行。

几何库返回的多边形可能包含内环，但画布只复制外环。被挖掉的内部区域重新变成实心。

**已复现：** 面积 400 的正方形减去内部面积 100 的正方形，预期结果为 300，实际结果仍为 400。

**修复及验收：** 先确定标注模型如何表示内环及多部分对象，再统一编辑、显示和导出；如果暂不支持孔洞，应在该操作中明确拒绝，不能静默生成错误几何。验收包含内孔、多个分离区域、相切和空差集。

### R14 · P2 · 视频首帧时间戳非零时，仅首帧归零，后续帧没有减去起点

**位置：** [时间索引扫描](../IVAS/video/media.py#L143)。

代码把第一帧改为 0，并将原值赋给局部变量 `origin`，但没有用这个起点修正后续时间戳，导致首帧和后续帧不在同一时间基准。

**已复现：** 输入解码时间 `[1000, 1040, 1080]` 得到 `[0, 1040, 1080]`；查询 40 ms 返回第 0 帧，预期为第 1 帧。该结果来自受控解码器样本，尚未用具有该时间特征的实际媒体验证后端行为。

**修复及验收：** 为所有帧统一归一化，并让异常时间戳回退沿同一基准处理。验收非零起点、重复/倒退时间戳、VFR 和末帧定位。

### R15 · P2 · 同路径图片发生变化后，SAM 编码缓存仍使用旧图像

**位置：** [SegAnyThread 缓存命中判断](../IVAS/widgets/mainwindow.py#L370)。

缓存只比较索引和路径，没有比较文件签名。主界面已有文件变化检测，但重新提交相同路径时，编码线程仍可以命中旧特征。

**已复现：** 同路径先写红图，再改为蓝图并再次请求编码；编码函数只执行一次，缓存像素仍为 `[255,0,0]`，磁盘图像为 `[0,0,255]`。

**修复及验收：** 请求和缓存键都包含文件身份/大小/修改时间及模型代次，必要时使用内容摘要；前后端用同一判断。验收覆盖图片替换、重新抽帧、目录切换和模型切换。

### R16 · P2 · 关闭窗口未统一处理所有后台任务

**位置：** [closeEvent](../IVAS/widgets/mainwindow.py#L4604)、[文本任务创建](../IVAS/widgets/text_prompt_dock_widget.py#L236)。

关闭流程等待点/框推理，调用视频工作区 shutdown，并处理版本检查及 GPU 监视；没有统一管理文本推理、图像编码、模型加载、下载和批处理。文本任务以控件为 Qt 父对象，生命周期尤其需要明确。

**已复现：** 用等待中的父控件线程代替耗时文本任务，调用真实关闭流程后，关闭事件被接受，线程仍在运行，也没有收到中断请求。本次没有实际触发进程崩溃；因此“退出时 QThread 被销毁导致崩溃”是这一缺口的风险，不是已观察结果。

**修复及验收：** 建立任务登记和统一关闭协议：拒绝新任务、请求取消、等实际结束后再销毁持有者。不要用强制 terminate 替代资源清理。验收在各种任务运行中关闭、取消关闭、关闭超时及结果已排队等情况。

### R17 · P2 · 模型下载未校验完整性，截断文件也显示下载完成

**位置：** [下载线程](../IVAS/widgets/model_manager_dialog.py#L68)。

读取到 EOF 就把临时文件移动到正式权重目录并发送完成信号，没有确认收到的字节数与预期一致。续传也未充分验证 Range 响应；读取已有缓存大小使用 `len(f.read())`，大权重会额外占用大量内存。

**已复现：** 模拟响应宣称 10 字节、实际仅 3 字节，最终文件只有 3 字节，仍发出 `(-2,-2)` 完成信号。未进行真实网络下载。

**修复及验收：** 校验长度与可获得的内容摘要；验证 206 / Content-Range，服务器不支持续传则安全重启下载；不完整文件留在临时目录。使用文件 stat 获取大小，所有请求设定超时。验收断流、响应忽略 Range、已完整缓存和摘要不符。

### R18 · P2 · 格式转换直接调用 QThread.run，长任务仍占用界面线程

**位置：** [ConverterDialog.apply](../IVAS/widgets/converter_dialog.py#L555)，582、605、635、656、678、698、721、739 行均直接 `.run()`；[视觉提示推理](../IVAS/widgets/visuall_prompt_dock_widget.py#L43) 也同步调用推理。

**代码路径确认：** 点击槽函数在界面线程执行，直接调用 `run()` 不会创建后台线程。因此转换期间界面无法正常处理重绘和取消点击。批量抽帧、EXIF 处理和标注校验也在 UI 线程循环。部分路径缺少异常时恢复控件的 finally 处理。本次未对大数据集进行响应时间基准测试。

**修复及验收：** 先修 R07 的共享状态，再将任务移到独立 worker，捕获不可变输入，通过信号汇报进度和逐文件结果。验收 UI 定时心跳、取消上限、错误后可重新执行。视觉提示复用现有点/框任务的过期结果保护。

### R19 · P2 · EXIF 工具接受空输出目录，将结果写入当前工作目录

**位置：** [目录检查与保存](../IVAS/widgets/process_exif_dialog.py#L44)。

`if not (image_root or save_root)` 只在两个字段都为空时阻止执行。只填输入目录会通过，`os.path.join("", image_name)` 变为相对路径。只填输出目录则可能在列举空输入路径时异常。

**已复现：** 输入一张带旋转 EXIF 的图片，输出目录留空，处理结果被写到测试进程当前目录。复现时已将当前目录隔离到临时文件夹，没有写入用户图片目录。

**修复及验收：** 同时验证输入、输出目录存在且可用；规范化路径并明确同目录覆盖语义。所有退出路径恢复按钮状态。验收两个单边为空、不可写输出、同目录和处理异常。

### R20 · P2 · 独立文本批标工具给所有对象相同 group，后续导出会合并实例

**位置：** [独立工具对象创建](../tools/auto_labeling_base_on_text_prompt/main.py#L248)。

**代码路径确认：** 每个预测对象固定 `group=1`。同一图片中同类的多个独立 mask，进入按 group 和类别合并的 COCO/YOLO/VOC 导出器时会被当作一个实例。没有运行该独立工具的真实 SAM3 模型；相同 group 在下游合并的行为已由 R09 样本确认。

**修复及验收：** 按模型实例分配 group，同一实例的多个连通区域才共用 group；复用主应用的轮廓和对象构造逻辑。验收两个同类独立实例、单个实例的多部分轮廓和空 mask。

### 额外完成的异常处理与优化

- `configs.py` 不再导入即写包目录；安装版和只读程序目录使用用户数据目录，支持 `IVAS_DATA_DIR`。YAML 使用原子保存；损坏文件在使用默认配置前备份，空配置、缺失快捷键及类别配置可启动。
- 批量框分割捕获模型和轮廓参数，整张图的编码与预测共用锁；兼容缺失可选 XML 字段，逐文件/对象报告错误。对象失败的图片保留原输出，其他文件继续处理。启动、取消、重试、关闭有明确状态。
- 视频 facade 的释放与追踪传播共用锁；模型切换检查在途任务；取消模型初始化后不继续加载第二个模型或发送完成信号。
- 远程检查异步请求，校验响应字段，连接失败或输入改变时清除旧的可用状态。标注校验继续检查同文件的后续对象；抽帧核查编码及写入结果并始终释放 capture，保留带点的文件名。
- 插件通知异常被隔离并显示；保存前插件失败中止保存。轮廓转换提取为无界面公共函数，转换输出及类别配置尽量复用同一原子写入实现。
- 发布流程依赖回归测试工作流；增加 Windows/Linux、Python 3.10/3.11 矩阵。安装元数据最低版本改为 3.10，与内置 SAM3 实际求值的联合类型注解一致，README 同步说明。

### 仍需真实环境验收的范围

上述通过结果不等于全模型、全平台验收。没有运行真实 CUDA 权重、在线下载服务或远程 SAM 服务，没有新构建 EXE/Docker，也没有执行远端 CI 矩阵。取消采取协作方式，正在执行的 GPU 算子和网络请求需在调用返回或超时后退出。下载在元数据提供 SHA256 时才做哈希校验；仅有长度和范围时不宣称完成权重来源认证。

长视频的峰值内存、索引及解码耗时仍需要代表性样本测量。第三方模型全面数值验证、大类整体拆分、独立工具整套 SAM3 副本合并及统一日志平台属于后续架构/性能工作；本次完成的是已确认缺陷和可独立验证的边界修复。
